# 04.3 Characterization Workflow

## Contents

**Tools:** CADET-GUI flow sheet diagrams; CADET-Process (Python).

**Python used:** A parameter dictionary, objective functions and carrying accepted values between fits.

**Introduces:** staged characterization, fixed versus fitted parameters, parameter transfer and checking mean delay against the complete curve.

1. Separate system and column delay
2. Carry the system estimate into the column fit
3. Check mean delay, curve shape and parameter values

Parameter Fitting showed how to estimate parameters from a tracer curve. Here, we ask **which parts of the setup contributed to that curve**, so each fitted parameter describes the right part of the experiment.

The goal is to estimate the **tracer-accessible porosity of a column connected to an instrument**, then carry that transport description into later binding studies. We use the synthetic experiments from RTD.

## Which part of the delay belongs to the column?

The detector sits after the **mixer, tubing and column**. At **6 mL/min**, the column-connected experiment gives a mean tracer delay of about **140 s**. We know the column dimensions, **10 cm × 2 cm**, and want to determine its **porosity**.

That measured delay includes two contributions:

**Measured mean delay = mean residence time in the mixer and tubing + mean residence time in the column**

The mixer and tubing are outside the column. In this setup, they contribute about **30 s**; the column contributes about **110 s**.

If we assign all 140 s to the column, the fitted porosity also accounts for liquid in the mixer and tubing. A good delay match would then give the wrong column parameter.

```{note}
The mean delay alone cannot separate **system volume** from **column porosity**: increasing either increases the predicted delay. We need an independent measurement of the instrument contribution. The **column-bypass experiment** provides it.
```

+++ {"slideshow": {"slide_type": "slide"}}

## Separate the experiments

Both experiments use **6 mL/min**. The bypass pulse characterizes the instrument; the breakthrough with the **10 cm × 2 cm column** includes both instrument and column transport.

| Experiment | What the signal tells us |
|---|---|
| 5 s pulse, column bypassed | About **30 s** instrument delay, corresponding to **3 mL** system volume |
| Continuous tracer feed, column connected | About **140 s** total delay, containing both instrument and column contributions |

Carry the bypass result into the column fit: fix the system volume at **3 mL**, then adjust only porosity. The column must account for the remaining **approximately 110 s**. This is the parameter transfer we want to demonstrate.

The supplied calculations use the appropriate mean delay for each signal: a pulse centroid for the bypass and the integrated step response for breakthrough.

## Accept the system result

The RTD bypass experiment established a system volume near **3 mL**. This notebook supplies that checkpoint so it can be run independently. Optimization Essentials used a column-only tracer curve; here, the measurement includes instrument transport as well.

Store accepted values in a dictionary, using SI units. Keep the accepted system volume fixed while fitting the column; do not let porosity compensate for an unmodelled instrument delay.

```{code-cell} ipython3
# Carry the accepted system result into the next characterization step.
accepted_parameters = {"system_volume": 3e-6}  # m³
column_volume = np.pi * 0.02 ** 2 * 0.1 / 4  # 10 cm × 2 cm column
```

The mean-delay model now contains both contributions:

$$
\tau_\mathrm{total}=\frac{V_\mathrm{system}+\varepsilon_t V_\mathrm{column}}{Q}.
$$

Only **porosity** changes in this fit. The flow rate, column geometry and accepted system volume stay fixed. The mean delay identifies volume; fitting dispersion requires the full curve as in Parameter Fitting.

```{code-cell} ipython3
# Separate the fixed instrument delay from the part assigned to the column.
_ = plot_delay_contributions(
    accepted_parameters["system_volume"] / flow_rate, measured_total_delay,
)
```

## Fit the column parameter

Define porosity bounds **0.2–0.6**, then minimize the squared difference from the measured breakthrough delay. The dictionary supplies the accepted system contribution.

```{code-cell} ipython3
from CADETProcess.optimization import OptimizationProblem

packing_problem = OptimizationProblem("column_packing")
```

```{code-cell} ipython3
:tags: [solution]

packing_problem.add_variable("porosity", lb=0.2, ub=0.6)

def packing_error(x):
    predicted_delay = (
        accepted_parameters["system_volume"] + x[0] * column_volume
    ) / flow_rate
    return (predicted_delay - measured_total_delay) ** 2

packing_problem.add_objective(packing_error, name="packing_error")
```

```{code-cell} ipython3
# Run the supplied fit and record the accepted porosity.
from CADETProcess.optimization import NelderMead

packing_optimizer = NelderMead()
packing_optimizer.n_max_iter = 100
packing_results = packing_optimizer.optimize(packing_problem, x0=[0.4])
accepted_parameters["porosity"] = float(packing_results.x[0, 0])
print(f"Accepted porosity: {accepted_parameters['porosity']:.3f}")
predicted_total_delay = (
    accepted_parameters["system_volume"] + accepted_parameters["porosity"] * column_volume
) / flow_rate
print(f"Predicted total delay: {predicted_total_delay:.2f} s")
print(f"Measured total delay: {measured_total_delay:.2f} s")
```

## Check what was assigned to the column

Without the accepted system volume, a column-only calculation would assign the entire measured delay to the column. It would give an apparent porosity near **0.45**, rather than the corrected value near **0.35**.

```{code-cell} ipython3
# Compare the corrected estimate with a column-only interpretation of the same data.
apparent_porosity = measured_total_delay * flow_rate / column_volume
print(f"Ignoring the system: {apparent_porosity:.3f}")
print(f"Including the accepted system volume: {accepted_parameters['porosity']:.3f}")
_ = plot_porosity_transfer(apparent_porosity, accepted_parameters["porosity"])
```

The apparent porosity is also between **0 and 1**. That makes it a possible volume fraction, but does not establish that the column model is correct: it has absorbed the instrument's delay.

## A matching delay can hide the wrong curve

The [synthetic reference](../../02%20CADET%20Fundamentals/resources/first_steps/generate_breakthrough_data.py) was generated with column dispersion **`1e-7` m²/s**. The supplied cell overlays the complete breakthrough curves and reports their mean delays and concentration errors.

```{note}
Both curves have almost the same **mean delay**, so our delay objective cannot distinguish their dispersion. The larger dispersion spreads the breakthrough front and gives a larger **full-curve error**. Carry the porosity estimate forward, then use the complete tracer curve to estimate dispersion, as in Parameter Fitting.
```

## Summary

| Stage | Experiment | Keep fixed from earlier stages |
|---|---|---|
| System transport | Bypass tracer pulses | Known flow rates and geometry |
| Column transport | Nonbinding tracers | System transport |
| Binding | Breakthroughs and elution gradients | System and column transport |

Different tracers can help distinguish accessible pore volumes; breakthrough and gradient experiments constrain binding capacity and salt dependence. Each stage needs measurements that contain information about its parameters.

**Model parameters describe the setup; operating variables define the process we want to improve.**
