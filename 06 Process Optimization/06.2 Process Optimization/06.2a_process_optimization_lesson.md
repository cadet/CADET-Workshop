# 06.2 Process Optimization

## Contents

**Tools:** CADET-Process (Python).

**Python used:** Parameter targets, evaluator dependencies, objective directions and result selection.

**Introduces:** nested simulation/fractionation evaluation, productivity maximization, purity constraints and cyclic stationarity.

1. Choose process variables
2. Simulate and optimize collection windows
3. Evaluate one candidate
4. Optimize and verify the selected process

In Fractionation, collection windows changed while the process stayed fixed. Now vary **feed duration** and **cycle time**, then determine suitable collection windows for each candidate.

The goal is higher average productivity for **A and B**, with each product pool at **at least 95% purity**.


+++ {"slideshow": {"slide_type": "slide"}}

## Choose the process variables

Use the same two-protein Langmuir batch-elution setup as in the fractionation lesson: a **60 cm × 2.4 cm** column at **60 mL/min**. The baseline feeds for **1 min** in a **10 min** cycle.

Vary cycle time between **8 and 15 min**, and feed duration between **20 and 90 s**. The model uses seconds, so convert minute values with `* 60`.


```{code-cell} ipython3

# Create an independent process for this optimization study.
process = batch_elution_process()
from CADETProcess.optimization import OptimizationProblem
optimization_problem = OptimizationProblem("batch_elution")
optimization_problem.add_evaluation_object(process)
```


```{code-cell} ipython3
:tags: [solution]

optimization_problem.add_variable(
    "cycle_time", targets=[process], parameter_path="cycle_time",
    lb=8 * 60, ub=15 * 60, normalization="linear",
)
optimization_problem.add_variable(
    "feed_duration", targets=[process], parameter_path="feed_duration.time",
    lb=20, ub=90, normalization="linear",
)
```

Keep at least **2 min** between the end of feeding and the next injection. The linear constraint expresses **feed duration − cycle time ≤ −120 s**. It also remains useful if the variable bounds are widened later.

```{code-cell} ipython3
:tags: [solution]

optimization_problem.add_linear_constraint(
    ["feed_duration", "cycle_time"], lhs=[1, -1], b=-2 * 60,
)
```

## Simulate repeated operation

A shorter cycle may leave material in the column for the next injection. Enable **cyclic stationarity**: simulate repeated cycles until successive chromatograms meet the simulator's convergence criteria.

The final cycle supplies the collection calculation. Reaching a fixed number of cycles alone would not establish stationarity.


```{code-cell} ipython3

from CADETProcess.simulator import Cadet
process_simulator = Cadet()
process_simulator.evaluate_stationarity = True
optimization_problem.add_evaluator(process_simulator)
```


+++ {"slideshow": {"slide_type": "slide"}}

## Determine the collection windows

Register `FractionationOptimizer` as the next evaluator, using the **95% purity** requirement introduced in Fractionation. It chooses cut times for the simulated chromatogram.

**Cycle time and feed duration → simulation → collection windows → performance**

The process optimizer changes operating conditions; the fractionation optimizer adjusts collection windows inside each evaluation.


```{code-cell} ipython3

from CADETProcess.fractionation import FractionationOptimizer
fractionation_optimizer = FractionationOptimizer()
fractionation_optimizer.optimizer.catol = 1e-4  # Absolute purity-constraint tolerance.
optimization_problem.add_evaluator(
    fractionation_optimizer,
    kwargs={
        "purity_required": [0.95, 0.95],
        "allow_empty_fractions": False,
        "ignore_failed": False,
    },
)
```


+++ {"slideshow": {"slide_type": "slide"}}

## Maximize productivity at the required purity

`Productivity(ranking=[1, 1])` returns the average productivity of A and B. Positive productivity should be **maximized**, so set `minimize=False`.

The explicit purity constraint uses `comparison_operator="ge"`, meaning **greater than or equal to**. The objective and constraint share the same simulation and fractionation results. The fractionation solver uses a purity-constraint tolerance of **0.0001**, so the reported purity can differ slightly from the requested bound.


```{code-cell} ipython3
:tags: [solution]

from CADETProcess.performance import Productivity, Purity
productivity = Productivity(ranking=[1, 1])
optimization_problem.add_objective(
    productivity, name="average_productivity", minimize=False,
    requires=[process_simulator, fractionation_optimizer],
)
purity = Purity()
optimization_problem.add_nonlinear_constraint(
    purity, name="product_purity", n_nonlinear_constraints=2,
    bounds=[0.95, 0.95], comparison_operator="ge",
    requires=[process_simulator, fractionation_optimizer],
)
```

## Check one candidate first

Evaluate the **10 min cycle / 60 s feed** baseline. The objective should be positive and both pool purities should be near or above **0.95**, within numerical tolerances.

This check catches a wrong parameter path or objective direction before running a full search.


```{code-cell} ipython3

baseline = [10 * 60, 60]
print("Baseline productivity:", optimization_problem.evaluate_objectives(baseline))
print("Baseline pool purities:", optimization_problem.evaluate_nonlinear_constraints(baseline))
```


+++ {"slideshow": {"slide_type": "slide"}}

## Run a short search

Use `U_NSGA3` with **8 candidates** and **3 generations**. `n_max_iter` is the common iteration-limit option; for this population optimizer, it limits generations.

This is a small demonstration run. Inspect its progress before increasing the evaluation budget.


```{code-cell} ipython3

from CADETProcess.optimization import U_NSGA3
optimizer = U_NSGA3()
optimizer.n_cores = 1
optimizer.pop_size = 8
optimizer.n_max_iter = 3
optimizer.seed = 42
results = optimizer.optimize(optimization_problem, x0=baseline)
print("Selected [cycle time, feed duration] / s:", results.x)
print("Average productivity:", results.f)
_ = results.plot_convergence("objectives")
plt.show()
```

## Verify the selected process

Apply the selected values explicitly, simulate again to stationarity, and show its collection windows and performance. Check purity and recovery alongside productivity before accepting an operating point.


```{code-cell} ipython3

# Apply the selected operating point and show the resulting product pools.
process.cycle_time = float(results.x[0, 0])
process.feed_duration.time = float(results.x[0, 1])
selected_simulation = process_simulator.simulate(process)
selected_fractionation = fractionation_optimizer.optimize_fractionation(
    selected_simulation, purity_required=[0.95, 0.95],
    allow_empty_fractions=False,
)
print(selected_fractionation.performance)
_ = selected_fractionation.plot_fraction_signal()
plt.show()
```

```{dropdown} Separate productivity and recovery objectives
For a trade-off study, add `Productivity()` and `Recovery()` as separate objectives, each with `n_objectives=2`, `minimize=False` and the same `requires` chain. Keep the purity lower bound. A multi-objective result offers several trade-offs rather than a single best operating point.
```
